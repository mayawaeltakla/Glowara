# تقرير تسليم Glowara — النسخة المصدرية

**تاريخ التقرير:** 28 أكتوبر 2026  
**نطاق التسليم:** كود Flutter/Dart مصدري + توثيق، وليس ملف APK أو نشر ويب مُتحققًا منه.

## 1. الخلاصة التنفيذية

تم بناء هيكل تطبيق **Glowara** كاملًا من ناحية الملفات والشاشات والطبقات الأساسية: ثمانية أقسام وظيفية، واجهة عربية/إنجليزية مع RTL/LTR، ثلاث لوحات ألوان في الوضعين الفاتح والداكن، تخزين محلي عبر sembast، مستودع لكل نطاق، ومصادقة محلية.

**لكن المشروع لم يُترجم ولم يُحلَّل ولم يُختبر ولم يُبنَ** في بيئة العمل هذه، لأن Flutter/Dart SDK لم يكونا متوفرين. لذلك:

- لا توجد نتائج `flutter analyze` أو `flutter test` يمكن الادعاء بها.
- لا توجد نسخة APK ولا نسخة Web مبنية.
- مجلدا `android/` و`web/` غير موجودين بعد؛ ينشئهما سكربت الإعداد.
- الكود خضع لمراجعة نصية/يدوية فقط، وقد تظهر أخطاء أنواع أو واجهات حزم عند أول تشغيل حقيقي.

**لا يصح وصف هذا التسليم بأنه «منتج نهائي جاهز للنشر».** هو أساس مصدري متقدم يحتاج خطوة تحقق وبناء على جهاز فيه Flutter.

### تحسينات حديثة أُضيفت قبل التسليم

- تكرار المهام أصبح ظاهرًا في الحوار ويُوسَّع في `forDay`، مع توضيح أن الإتمام على مستوى السلسلة.
- دعم إعادة تفعيل العادات غير النشطة، واستبعاد غير النشطة من الجدولة والرئيسية والإحصاءات.
- التحقق من ملكية مادة الدراسة ومجموعة بطاقات الاختبار قبل العرض.
- الاستيراد يعيد ربط كل السجلات بالحساب الحالي، بما فيها مفاتيح الماء/المزاج/الملف المركّبة، ويرفض الملفات غير التابعة لـ Glowara أو ذات مخطط أحدث.
- فشل ترحيل `shared_preferences` القديم لم يعد يمنع فتح قاعدة البيانات.
- حذف البيانات/الحساب يمسح مفاتيح النسخة القديمة، كي لا يعيد الترحيل بيانات قديمة عند التشغيل التالي.
- عرض النسخة المحفوظة من القرآن قبل محاولة الشبكة، ومنع تراجع موضع الآية.
- رسالة إلغاء إتمام العادة لم تعد تقول «تم تسجيل العادة».
- إحصاءات العناية تُعتبر بيانات حقيقية عند وجود خطوات منجزة.
- تمرير `userId` إلى `CareRepository.doneStepIds` لتحسين عزل سجلات العناية.
- تحديث اسم المستخدم في سجل `users` و`current_user` معًا، كي لا يعود الاسم القديم بعد إعادة الدخول.
- تنظيف متحكمات بعض الحوارات في الإعدادات والصحة والدراسة والمذكرات والقرآن، وتحديث نصوص AR/EN المرتبطة.

## 3. ما لم يُنفَّذ

| البند | الحالة والسبب |
|---|---|
| المزامنة السحابية الآمنة بين الأجهزة | **غير منفذة.** لا يوجد خادم أو مصادقة سحابية، وبالتالي لا يوجد حل تعارضات فعلي. هذا جزء أساسي من المتطلبات الأصلية ولم يكتمل. |
| إشعارات الخلفية | **غير موصولة.** تذكير الماء داخل التطبيق فقط عند فتح الرئيسية، وخارج ساعات الهدوء. |
| تذكيرات المهام/العادات/المذكرات | **غير منفذة.** لا توجد إشعارات مجدولة لهذه العناصر. |
| شارات/إنجازات مستقلة | **غير منفذة.** قسم التقدم يعرض إحصاءات وأهدافًا شهرية، دون نظام شارات. |
| تقويم شهري كامل | **غير منفذ.** توجد أسبوعية ومنتقي تاريخ وعرض يومي، لا شبكة شهر كاملة. |
| مواقيت الصلاة | **غير منفذة.** التطبيق يسجل إتمام الصلوات فقط، دون حساب أوقات. |
| نصوص الأذكار والدعاء | **لا تُعرض.** المصدر محدد مبدئيًا لكن الربط والمراجعة البشرية لم يُنفّذا؛ لا يوجد نص ديني مؤلف من الذاكرة. |
| تشفير المذكرات | PIN قفل وصول محلي، **وليس تشفيرًا**. لا يحمي من نسخ ملف القاعدة. |
| قفل المذكرات تلقائيًا | غير منفذ؛ يبقى القسم مفتوحًا بعد مغادرة التطبيق حتى إعادة التشغيل. |
| منهج لغوي جاهز | غير مضمّن؛ المحتوى من بطاقات ودروس المستخدمة فقط. |
| تتبع غذائي/سعرات | ملاحظات وجبات فقط، وليست قاعدة أطعمة أو حساب سعرات. |
| استعادة كلمة المرور | غير متاحة؛ لا بريد تحقق ولا خادم. |
| تغيير كلمة المرور | غير متاح من الإعدادات؛ لا يوجد نموذج لتغييرها دون حذف الحساب. |
| تصدير/استيراد كملف | يتم عبر الحافظة (Clipboard) فقط، وليس عبر منتقي ملفات أو مشاركة نظامية. |
| خيارات العرض الإضافية | `compactCards` و`useWesternDigits` موجودة في النموذج لكنها غير مربوطة بواجهة الإعدادات. |
| تصدير حساب واحد | التصدير يشمل كل الحسابات المحلية على الجهاز، دون كلمات المرور، ثم يعيد الاستيراد ربطها بالحساب الحالي. |
| ترقيات مخطط تلقائية | لا توجد بعد الإصدار الأول؛ تغيير شكل الموديل يحتاج مسار ترحيل صريحًا. |
| عزل صفّي كامل | `HabitLog` بلا `userId` ويعتمد على تفرد معرف العادة؛ بعض الكيانات مرتبطة بمعرف أب. الفحوص في الواجهة لا تساوي عزلًا على مستوى قاعدة البيانات. |
| إتمام كل تكرار مهمة على حدة | **غير موجود.** الإتمام على مستوى السلسلة (قرار تصميم موثق). |
| تفضيلات لكل حساب | اللغة/الثيم/التذكيرات/هدف الماء/PIN/موضع القرآن مشتركة على مستوى الجهاز. |
| نسخ APK/Web | غير مبنية. |
| مجلدات المنصات | `android/` و`web/` غير موجودة؛ ينشئها `tool/setup_windows.ps1` أو `flutter create` في مجلد مؤقت. |
| هوية التطبيق على المتجر | لا توجد أيقونة/شاشة بداية مخصصة أو إعداد توقيع APK؛ السقالات الافتراضية ستُستخدم عند البناء. |
| اختبارات التخزين والواجهة والتكامل | غير موجودة. |
| مستودع Git | لا يوجد مستودع Git مهيأ في مجلد المشروع؛ التغييرات غير ملتزمة. |

## 5. القيود والمخاطر المهمة

1. **أول `flutter analyze` قد يفشل** بسبب اختلافات دقيقة في واجهات الحزم، خصوصًا sembast و`go_router` وMaterial، أو بسبب أنواع اختيارية.
2. **الاستيراد ليس معاملة ذرّية**: قد ينجح جزء ويفشل جزء، ولا توجد rollback. خذ نسخة احتياطية قبل الاستيراد.
3. **الترحيل القديم غير مختبر**، ولا ينقل سجلات `users`؛ قد تُستعاد جلسة `current_user` دون سجل مصادقة، وقد لا تظهر سجلات قديمة بلا `userId` بعد إنشاء حساب لأن المستودعات تصفّي بـ `userId`. فشل الترحيل لا يمنع فتح التطبيق، لكنه قد يخفي بيانات قديمة.
4. **الصور/الخطوط**: التطبيق يستخدم خطوط النظام ولا يضمّن Amiri/Tajawal؛ الجمالية العربية تعتمد على توفر خطوط الجهاز.
5. **الويب**: IndexedDB مرتبط بأصل (origin) المتصفح؛ مسح بيانات الموقع يمسح البيانات، ووضع التصفح الخاص لا يضمن الاستمرار.
6. **القرآن**: يعتمد على خدمة خارجية عند أول تحميل؛ لا حزمة قرآن مدمجة. التوفر والحدود وشروط الاستخدام مسؤولية النشر.
7. **الخصوصية**: قاعدة البيانات غير مشفرة، وPIN لا يحمي من الوصول إلى ملفات التطبيق، والتصدير JSON نصي غير مشفّر. لا تُستخدم لبيانات حساسة حقيقية قبل تشفير فعلي ومراجعة أمنية.
8. **الحساب**: محلي فقط؛ لا يمكن الدخول به على جهاز آخر، و`deleteAccount()` يمسح كل البيانات المحلية لا الحساب الحالي فقط.
9. **النسخ الاحتياطي**: التصدير يشمل بيانات كل الحسابات المحلية؛ لا تشاركه كأنه خاص بحساب واحد.
10. **التعريب**: `l10n.yaml` وملفات ARB غير مستخدمة؛ النصوص الفعلية في `lib/core/localization/`. تعديل ARB لا يغيّر الواجهة.
11. **التكرار**: إتمام سلسلة كاملة قد يخالف توقع من يريد إنجازًا مستقلًا لكل يوم؛ هذا قرار تصميم يجب اختباره مع المستخدمة.
12. **لا Git**: لا يوجد تاريخ التزامات يمكن الرجوع إليه. أنشئ مستودعًا ونسخة احتياطية قبل التعديل.
13. لم تُجرَ مراجعة إتاحة (a11y) أو تباين ألوان أو أداء على أجهزة حقيقية؛ هذه مراجعات مطلوبة قبل النشر.

## 6. خطوات التحقق المطلوبة قبل النشر

على جهاز Windows فيه Flutter 3.24.0 وAndroid SDK:

```powershell
cd C:\path\to\glowara
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
.\tool\setup_windows.ps1 -InstallFlutter
```

أو يدويًا:

```powershell
flutter pub get
flutter analyze
flutter test
flutter run -d web-server --web-port 8080
```

ثم:

```powershell
flutter build web --release
flutter build apk --release
```

مع اختبار يدوي على الأقل لـ:

- إنشاء حساب ثم إغلاق التطبيق وإعادة فتحه.
- إضافة مهمة/عادة/مذكرة/مزاج ثم إعادة التشغيل.
- مهمة يومية وأخرى أسبوعية، والتأكد من سلوك الإتمام على مستوى السلسلة.
- فتح سورة مع الإنترنت ثم إعادة فتحها دونه.
- تصدير JSON واستيراده في حساب جديد، والتأكد من إعادة الربط ورفض ملف غير صالح.
- تفعيل PIN ثم فتح المذكرات، مع إدراك أنه ليس تشفيرًا.
- تبديل اللغة والثيم وإعادة التشغيل.
- تعطيل عادة وإعادة تفعيلها.
- اختبار شاشة تفاصيل مادة تخص حسابًا آخر (يجب ألا تُعرض).

**لا تُعلن الجاهزية حتى ينجح `flutter analyze` و`flutter test`، ويتم بناء APK/Web، وتُنفَّذ هذه الفحوص اليدوية.**

## 8. الإقرار النهائي

التسليم الحالي **كود مصدري وتوثيق**، وليس نسخة تشغيلية متحققة. ما تم إنجازه كبير في الهيكل والوظائف، لكن المتطلبات التي تعتمد على خادم (المزامنة الآمنة وحل التعارضات) أو على تكامل منصة (الإشعارات الخلفية) أو على مراجعة محتوى (القرآن والأذكار) **لم تكتمل**، ويجب عدم الادعاء بها.

أي ادعاء بأن التطبيق «يعمل» أو «مكتمل» أو «جاهز للنشر» قبل تنفيذ أوامر التحليل والاختبار والبناء أعلاه غير صحيح.
